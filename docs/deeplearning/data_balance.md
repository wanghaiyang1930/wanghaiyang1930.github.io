# 不平衡数据的过采样：稀有类别不必完全配平

## 1. 论文信息

本文总结论文 **The Effect of Oversampling Method for Imbalanced Data**（2008）。论文研究的问题是：当少数类（minority class）样本远少于多数类（majority class）时，应该把少数类过采样到什么程度，才能改善分类效果，而不是简单地把所有类别强行补成相同数量。

- **研究主题**：不平衡数据、过采样、分类性能
- **核心问题**：少数类是否应该过采样到与多数类 `1:1`？
- **核心结论**：通常没有必要完全配平；在论文讨论的实验条件下，少数类与多数类保持约 `1:2`～`1:3` 的比例，往往比 `1:1` 更合适。
- **原始论文**：[KISS 论文页面](https://kiss.kstudy.com/DetailOa/Ar?key=50867502)

> 比例说明：`少数类:多数类 = 1:3`，表示少数类样本数约为多数类的三分之一，并不是“少数类占整个数据集的三分之一”。

## 2. 问题背景

### 2.1 什么是不平衡数据

二分类数据可以表示为：

```text
多数类：N_majority
少数类：N_minority
```

当：

```text
N_minority << N_majority
```

训练集的经验分布就会被多数类主导。以欺诈检测、故障检测、医学诊断和稀有目标检测为例，真正重要的事件通常恰恰是样本数量较少的少数类。

### 2.2 只看准确率会掩盖问题

假设多数类占 `99%`，少数类占 `1%`。如果分类器把所有样本都预测成多数类，准确率仍然可以达到 `99%`，但少数类的召回率为 `0`。

因此，不平衡数据不能只使用 Accuracy 评价，还应同时关注：

- **少数类召回率（Recall）**：少数类样本被找出的比例；
- **少数类精确率（Precision）**：预测为少数类的样本中真正属于少数类的比例；
- **F1-score**：Precision 和 Recall 的调和平均；
- **G-mean**：同时衡量少数类和多数类识别能力；
- **ROC-AUC 或 PR-AUC**：尤其是少数类很稀少时，PR-AUC 往往更能反映实际效果。

## 3. 过采样的基本机制

过采样不改变多数类，而是增加少数类在训练过程中的出现次数，使分类器看到更多少数类样本。

### 3.1 随机复制过采样

最基本的方法是从少数类中有放回地抽样：

```text
原始少数类：{x1, x2, x3}
过采样后：  {x1, x2, x3, x1, x3, x2, ...}
```

若原始样本数为 `N_minority`，目标少数类样本数为 `N'_minority`，则过采样倍数为：

```text
r = N'_minority / N_minority
```

目标比例为：

```text
ρ = N'_minority / N_majority
```

论文的关键不是“是否过采样”，而是如何选择 `ρ`。论文的实验结论倾向于：

```text
ρ ≈ 1/3 ～ 1/2
```

也就是：

```text
少数类:多数类 ≈ 1:3 ～ 1:2
```

而不是：

```text
少数类:多数类 = 1:1
```

### 3.2 为什么不直接补到 1:1

完全配平会带来两个风险：

1. **重复样本过多**：如果少数类原始样本非常少，补到多数类规模需要反复复制同一批样本。
2. **过拟合少数类**：模型可能记住少数类样本，而不是学习少数类的稳定特征。

另一方面，如果完全不处理不平衡，分类器又容易偏向多数类。`1:2`～`1:3` 是一种折中：提高少数类的训练权重，同时保留多数类对真实数据分布的约束。

## 4. 论文技术要点

### 4.1 过采样比例是连续的超参数

过采样不应该被理解成只有两种选择：

```text
不采样  vs.  采样到 1:1
```

更合理的做法是把目标比例作为超参数进行搜索，例如：

```text
1:10 → 1:5 → 1:3 → 1:2 → 1:1
```

然后通过验证集比较各比例下的少数类召回率、F1、G-mean 和整体误报率。

### 4.2 原始不平衡程度会影响过采样收益

论文指出，当原始少数类与多数类差距较大时，过采样更可能带来明显收益。特别是当原始比例超过 `1:5` 时，直接训练容易产生明显的多数类偏置，适度增加少数类样本能够改善分类结果。

但这不意味着原始比例越极端，就应该把少数类无限复制到 `1:1`。原始不平衡越严重，越需要结合少数类样本的多样性、噪声比例和任务代价选择目标比例。

### 4.3 过采样改变的是训练分布，不应改变测试分布

过采样只应作用于训练集：

```text
原始数据
   │
   ├── 训练集：只对少数类过采样
   │
   └── 验证集/测试集：保持原始分布
```

如果先对完整数据集过采样，再划分训练集和测试集，会产生两个问题：

- 同一个原始样本的副本可能同时进入训练集和测试集，造成数据泄漏；
- 测试集被人为配平，评估结果无法代表真实部署分布。

因此，正确顺序是先划分数据，再仅对训练集执行过采样。

### 4.4 过采样与分类阈值调整是两条不同路径

过采样通过改变训练阶段的类别出现频率，影响模型学习到的决策边界；阈值调整则是在推理阶段改变预测规则：

```text
过采样：改变训练数据分布
阈值调整：改变预测决策阈值
类别权重：改变损失函数中不同类别的代价
```

三者可以单独使用，也可以组合使用，但组合时必须在验证集上重新校准阈值，不能直接假设 `0.5` 仍然是最优阈值。

## 5. 实验结论的工程解释

可以把论文结论概括为以下决策规则：

| 场景 | 建议 |
|---|---|
| 少数类与多数类接近 | 可以不做过采样，先比较原始训练结果 |
| 原始比例约为 `1:5` 或更极端 | 尝试对少数类做适度过采样 |
| 少数类样本很少、重复度高 | 不建议直接过采样到 `1:1` |
| 误报成本较高 | 使用较低的目标比例，并结合阈值调节 |
| 漏检成本较高 | 尝试提高少数类比例，同时重点观察 Recall 和 PR-AUC |
| 少数类内部差异很大 | 优先增加真实多样性或使用合成增强，而不是单纯复制 |

最重要的经验是：

> **配平的目标不是让每个类别数量相同，而是让模型既能看到稀有类别，又不丢失多数类别对真实分布的约束。**

## 6. 推荐的实现流程

```python
from sklearn.model_selection import train_test_split
from sklearn.metrics import classification_report, average_precision_score

# 1. 先划分数据，避免过采样导致数据泄漏
X_train, X_test, y_train, y_test = train_test_split(
    X, y,
    test_size=0.2,
    stratify=y,
    random_state=42,
)

# 2. 只在训练集上选择目标比例，例如少数类:多数类 = 1:3
#    实际项目中可使用 RandomOverSampler(sampling_strategy=1/3)
#    并在验证集上比较 1/5、1/3、1/2、1/1 等比例。

# 3. 使用原始分布的验证集/测试集评估
#    重点报告少数类 Recall、F1、PR-AUC 和混淆矩阵。
```

实际训练时，应把目标比例当作验证集上的超参数，而不是固定写死为 `1.0`。如果使用交叉验证，过采样操作也必须放进每个训练折内部，不能在交叉验证之前完成。

## 7. 与其他方法的关系

| 方法 | 改变位置 | 主要优点 | 主要风险 |
|---|---|---|---|
| 随机过采样 | 训练样本分布 | 简单、易实现 | 重复样本导致过拟合 |
| 欠采样 | 训练样本分布 | 降低训练成本 | 丢失多数类信息 |
| SMOTE | 训练样本分布 | 通过插值增加少数类多样性 | 可能在类别边界生成噪声 |
| 类别权重 | 损失函数 | 不复制样本 | 权重需要调参 |
| Focal Loss | 损失函数 | 强调困难样本 | 主要控制样本难度，不直接改变类别比例 |
| 阈值调节 | 推理决策 | 不改训练数据 | 需要可靠的验证集校准 |

论文的核心经验也适用于这些方法：无论是复制、合成还是加权，都不应默认追求 `1:1`，而应根据验证集指标和业务代价寻找适度的平衡点。

## 8. 需要避免的误读

1. **`1:3` 不是所有任务的固定定律**：它是论文实验得到的经验范围，不能脱离数据规模、噪声和任务代价直接套用。
2. **过采样不等于增加真实信息**：随机复制只增加少数类出现频率，不会增加新的语义变化。
3. **训练集配平不等于线上分布配平**：线上数据通常仍然保持长尾分布，评估必须保留真实分布。
4. **不要只看 Accuracy**：过采样后 Accuracy 可能下降，但少数类 Recall、F1 或 PR-AUC 可能明显提升。
5. **不要把论文结论误写成 SMOTE 结论**：该论文讨论的是 oversampling 的比例效果；在没有完整实验正文依据时，不能断言其结论专门来自 SMOTE 或某一种合成算法。

## 9. 总结

这篇论文最值得记住的技术观点是：

```text
稀有类别需要被强化，但不一定要被强化到与多数类别一样多。
```

在原始数据明显不平衡时，可以先尝试把少数类补到多数类的约 `1/3～1/2`，即少数类:多数类约为 `1:3～1:2`，再根据验证集上的少数类 Recall、F1、PR-AUC、误报成本和过拟合情况进行调整。

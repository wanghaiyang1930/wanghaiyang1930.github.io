# 为什么 SFT 微调可以冻结部分层而只更新另一部分层

## 1. 文档目的

本文回答一个具体问题：在 SFT（Supervised Fine-Tuning）中，为什么可以把一部分层的参数冻结、只让另一部分层参与梯度更新，而模型仍然能学到新任务？

本文分四个层次回答：

1. **机制层**：为什么技术上做得到，冻结之后前向和反向到底发生了什么；
2. **表示层**：为什么分层冻结在表示学习上是合理的，而不是随便切一刀；
3. **优化层**：为什么少更新参数往往学得更稳、更不容易灾难性遗忘；
4. **工程层**：为什么在显存和时间预算下这是必须的选择。

结构与层号映射沿用 [`qwen3_5_9b_model_architecture.md`](qwen3_5_9b_model_architecture.md)，即 27 层视觉塔 + merger + 32 层混合语言主干（24 层 Gated DeltaNet + 8 层 Gated Full Attention）+ 独立 LM head。

> 免责声明：本文给出的是原理和判据，不是可以照抄的层号配方。任何冻结边界都必须通过消融实验验证。

## 2. 一句话结论

预训练已经把「通用能力」写进了参数里，SFT 要补的通常只是「输出格式与任务映射」这一小部分能力；这部分能力主要由靠近输出端的少数层承载，因此冻结其余层既不阻断学习，又能保住已有能力，还大幅降低显存与算力开销。

## 3. 机制层：冻结在计算图里究竟意味着什么

### 3.1 冻结不等于跳过

把一个参数设为 `requires_grad=False` 之后：

| 环节 | 冻结层 | 可训练层 |
|---|---|---|
| 前向计算 | 照常执行，照常产生激活 | 照常执行 |
| 反向传播中「对输入的梯度」 | **照常计算并继续往下传** | 照常计算 |
| 反向传播中「对权重的梯度」 | 不计算、不保存 | 计算并保存 |
| 优化器状态（Adam 的 m/v） | 不分配 | 分配，约每参数 8 bytes（FP32） |
| 参数是否变化 | 不变，可用 hash 校验 | 变化 |

关键点是第三行。冻结层依然是可微的函数，梯度可以「穿过」它。这就是为什么即使冻结了 `layers.0–23`，放在 `layers.24–31` 的 LoRA 也能收到有效梯度——梯度从 loss 出发，经过 LM head 和 final norm，到达第 31 层就已经进入可训练区域，不需要再往下走。

反过来说，如果可训练参数位于**底层**、冻结层位于**上层**，那梯度必须穿过整条冻结的上层链路才能到达底层。这条链路会衰减、旋转甚至压扁梯度信号，是「只训练底层」通常效果很差的原因之一。

### 3.2 冻结层的反向传播仍需要激活

一个常见误解是「冻结了就不用存激活」。实际上：

- 若冻结层**位于**可训练层之下（更靠近输入），它的激活对反向传播不再必要，可以省掉，这是显存节省的主要来源；
- 若冻结层**位于**可训练层之上（更靠近输出），梯度必须穿过它，链式法则需要它前向时的中间量，激活仍然要保留。

所以「解冻上层、冻结底层」不仅是表示学习上的选择，也是显存上最划算的排列。这正好解释了架构文档中为什么把 `layers.24–31` 而不是 `layers.0–7` 选为第一优先解冻区域。

### 3.3 数学表述

设网络为层的复合：

```text
loss = L( f_N( ... f_2( f_1(x; θ_1) ; θ_2) ... ; θ_N) )
```

对第 k 层权重的梯度是：

```text
∂loss/∂θ_k = (∂loss/∂h_N) · (∂h_N/∂h_{N-1}) · ... · (∂h_{k+1}/∂h_k) · (∂h_k/∂θ_k)
```

冻结第 k 层，只是让我们不去求最后一项 `∂h_k/∂θ_k`；中间的雅可比连乘项 `∂h_{j+1}/∂h_j` 与是否冻结无关，照样存在。因此冻结从不破坏计算图的连通性，只是在参数空间里把优化限制到一个低维子空间：

```text
θ = θ_pretrained + Δ,   其中 Δ 的支撑集被限制在可训练参数上
```

SFT 本质上是在这个受限子空间里做优化。问题于是变成：**这个子空间是否包含足够好的解？**下一节回答这一点。

## 4. 表示层：为什么受限子空间里仍然有好解

### 4.1 预训练已经把大部分能力学完了

SFT 的输入分布与预训练分布高度重叠：都是自然语言（本项目中还有自然图像）。SFT 要改变的是**条件分布的形状**，不是**特征提取器本身**：

| 能力 | 主要由谁承载 | SFT 是否需要改 |
|---|---|---|
| 子词切分、词法、拼写 | embedding + 底层若干层 | 基本不需要 |
| 语法、局部句法结构 | 底层到中层 | 基本不需要 |
| 世界知识、事实关联 | 中层 FFN 为主 | 通常不需要，改了容易破坏 |
| 抽象推理、任务组合 | 中层到上层 | 部分需要 |
| 指令跟随、输出风格、格式 | 上层 + final norm + LM head | **主要需要** |
| 新增 token 的表示与分类边界 | 新增 embedding 行 / LM head 行 | **必须训练** |

这张表是「上层优先解冻」的核心依据。SFT 数据量通常是 10³–10⁶ 条，相对 9B 参数来说信息量极小，它没有能力也没有必要重塑底层特征提取器。

### 4.2 层的功能是渐进特化的

视觉塔和语言主干都有一个经验规律：**越靠近输入的层越通用，越靠近输出的层越任务特化**。

在 Qwen3.5-9B 视觉塔上，这体现为 `blocks.0–8` 编码边缘、纹理和局部结构（这些对任何视觉任务都一样），而 `blocks.18–26` 编码接近语义的高层表示（这些才与具体下游任务相关）。这就是架构文档把视觉 LoRA 放在 `blocks.18–26` 而不是 `blocks.0–8` 的原因。

底层特征通用，意味着它们**不需要**改；把它们冻结不是牺牲，而是省下预算。

### 4.3 权重更新本身是低秩的

有一个更强的结论支撑「不必更新全部参数」：全参数微调所产生的权重变化 `ΔW` 在经验上具有很低的有效秩。也就是说，全参数微调虽然动了所有数字，但它实际探索的方向数远小于参数数。

这直接给出两种等价的省法：

1. **按层稀疏**：只让部分层的 `ΔW` 非零，即层冻结；
2. **按秩稀疏**：所有目标层都动，但把 `ΔW` 限制为 `B·A` 的低秩形式，即 LoRA。

两者可以叠加。架构文档的 E1 阶段（`layers.24–31` 上的 LoRA）正是同时施加了这两种约束——先按层缩小范围，再在范围内按秩压缩。

### 4.4 但要注意「小参数量 ≠ 低风险」

分层冻结的合理性有一个重要例外：**norm 参数和跨模态接口参数量很小，但影响面极大**。

- `model.language_model.norm` 只有 4,096 个参数，却决定进入 LM head 前的整体激活尺度；
- `model.visual.merger` 只占 checkpoint 的 0.42%，却是全部视觉 token 进入语言序列的唯一有参数通路；
- Gated DeltaNet 的 `A_log`、`dt_bias`、`conv1d` 控制递归状态的衰减行为，改动会影响长序列建模的稳定性。

这些模块动一下就会同时改变所有任务的行为，所以默认冻结的理由不是「参数少所以不值得训」，而是「影响广所以必须单独做消融」。

## 5. 优化层：为什么冻结常常让效果更好，而不只是更省

冻结不是纯粹的妥协，它在几个方面是主动的正则化手段。

### 5.1 抑制灾难性遗忘

全参数 SFT 的失效模式是：模型在目标任务上指标上升，但通用能力（多语言、代码、常识、本项目中的通用 VLM 行为）显著退化。原因是梯度会沿着「对当前 batch 最有利」的方向改写承载通用知识的参数，而 SFT 数据里没有任何信号约束这些能力不许掉。

冻结是最硬的约束：被冻结的参数逐位不变，其承载的能力**在数学上不可能退化**。这比 KL 正则、EWC、replay 更强——那些方法只是惩罚偏离，冻结是禁止偏离。这也是架构文档设置 3%/5% 保真门槛并要求打印「原始冻结参数训练前后 hash」的原因：hash 一致才能证明冻结真的生效了。

### 5.2 降低有效容量，抑制过拟合

可训练参数从 9.4B 降到几十 M，等价于把假设空间大幅缩小。当 SFT 数据只有几千到几万条时，这个缩小通常直接转化为更好的泛化——大模型在小数据上全参数微调很容易记住样本而非学到映射。

### 5.3 优化过程更稳定

- 可训练参数少 → 参数更新的噪声方差小 → 可以用更大学习率而不发散；
- 保持底层表示固定 → 上层看到的输入分布在整个训练过程中不漂移 → 收敛更快、对超参更不敏感；
- 全参数微调需要很小的学习率（常见 1e-5 量级）来避免破坏预训练权重，而 LoRA 可以用 1e-4 量级，因为其低秩增量初始为零且不直接改写原权重。

### 5.4 实验可解释性

如果每次都全参数微调，指标变化无法归因。按区域逐步解冻（架构文档的 E0→E5）让每一步只引入一个变量，才能回答「视觉特征是否需要适配」「LoRA 是否存在容量瓶颈」这类问题。这是分区冻结在科研意义上的价值，与省显存无关。

## 6. 工程层：预算约束下的必然选择

以 Qwen3.5-9B 为例，全参数 SFT 与冻结 + LoRA 的显存开销对比（BF16 权重、Adam 优化器、不计激活）：

| 项目 | 全参数微调 | 冻结原参数 + 上层 LoRA |
|---|---:|---:|
| 权重（BF16） | ~18.8 GB | ~18.8 GB |
| 梯度（BF16） | ~18.8 GB | 约几十 MB |
| Adam 状态（FP32 m+v） | ~75 GB | 约几百 MB |
| FP32 主权重副本（若使用） | ~37.6 GB | 不需要 |
| 量级合计 | 100 GB 以上 | 20 GB 量级 |

优化器状态是全参数微调的显存主项，而它**只对可训练参数分配**。这是冻结带来的最直接收益：可训练参数减少 100 倍，优化器状态也减少 100 倍。

除显存外还有：

- **反向计算量下降**：底层冻结后无需计算权重梯度，也可省去其激活缓存；
- **checkpoint 体积下降**：只需保存 LoRA 权重和新增 token 行，从 ~19 GB 降到几十 MB，便于多任务分支管理；
- **可组合性**：多个任务的 LoRA 共享同一份冻结底座，推理时按需加载，而非各存一份 9B 全量权重。

## 7. 决定冻结边界的判据

有了以上原理，实际选择边界时可以用下面的判据，而不是凭感觉切层。

### 7.1 先问「新任务离预训练分布有多远」

| 情形 | 建议可训练范围 |
|---|---|
| 只需改输出格式/风格，输入分布不变 | LM head 附近 + 上层少量层 |
| 新任务需要新的输出符号（如轨迹 token） | 必须包含新增 input embedding 行与新增 LM head 行 |
| 语义能力够但需要新的推理组合 | 上层若干完整周期的 LoRA |
| 输入模态的特征本身不适配（图像域偏移） | 追加视觉塔后段 LoRA |
| 任务与预训练分布差异极大 | 才考虑更深范围乃至全参数，并配 replay |

### 7.2 沿结构边界切，不要切在周期中间

Qwen3.5-9B 的语言主干是 8 次重复的四层周期（3 个 DeltaNet + 1 个 Full Attention）。只解冻 full-attention 层 27 和 31、而不动相邻的 DeltaNet 层，会得到一个既不完整又难以解释的配置：性能变化无法归因到「深度不够」还是「mixer 类型不匹配」。按完整周期解冻（24–31，然后 16–31）才能做出可比的消融。

视觉塔同理，按 9 个 block 一组切，保持三段等参数量。

### 7.3 必须打印验证，不能假设配置生效

冻结最常见的失败不是策略错，而是配置没生效。训练开始前应打印：

- 可训练参数的完整名称列表与各区域参数量；
- `target_modules` 实际命中的模块（`all-linear` 常会误伤视觉塔、merger、LM head）；
- 新增 token 行是否真的收到非零梯度；
- 训练前后冻结参数的 hash 是否一致。

在 Qwen3.5-9B 上尤其要检查 LoRA 是否覆盖了 24 个 DeltaNet 层——只匹配 `q_proj/k_proj/v_proj/o_proj` 的正则表达式只能命中 8 个 full-attention 层，会静默漏掉 75% 的语言层。

### 7.4 单向扩大，逐步放开

从「冻结一切，只训练必须训练的部分」开始，每次只放开一个区域，并从同一个基线分叉。若某一步没有带来显著的目标任务收益，就不应为了「更深的微调」继续扩大范围——每次扩大都在增加遗忘风险和成本。

## 8. 常见误解

| 误解 | 事实 |
|---|---|
| 冻结层在前向时被跳过 | 照常参与前向，只是不更新权重 |
| 冻结的层梯度传不过去 | 梯度照常穿过，只是不对其权重求梯度 |
| 冻结底层是因为底层不重要 | 恰恰因为底层承载最通用的表示，改动收益低、破坏风险高 |
| 参数少的层（norm）改了没影响 | norm 控制共享激活尺度，影响所有任务 |
| 只训练新增 input embedding 就够了 | `tie_word_embeddings=false`，新增 LM head 行必须单独训练 |
| LoRA 一定不如全参数微调 | 在 SFT 数据量下常常更好，因为遗忘更少、过拟合更少 |
| 解冻越多效果越好 | 目标指标可能提升，通用能力常同时退化；需看 Pareto 前沿而非单一指标 |
| 冻结只是省显存的妥协 | 同时是正则化手段和实验可解释性的前提 |

## 9. 关键结论

1. 冻结在机制上只是把优化限制到参数空间的一个子空间，不破坏计算图，梯度照常穿过冻结层。
2. 「解冻上层、冻结底层」在显存上最划算，因为可训练层之下的激活可以不保留，而之上的必须保留。
3. 受限子空间里存在好解，因为预训练已完成通用能力的学习，SFT 主要需要调整靠近输出端的任务映射；且经验上 `ΔW` 本身是低秩的。
4. 冻结是比 KL 正则或 replay 更硬的抗遗忘约束：被冻结的能力在数学上不可能退化。
5. 优化器状态只对可训练参数分配，是显存收益的主要来源，可让 9B 模型 SFT 从 100 GB 量级降到 20 GB 量级。
6. 参数量小不等于风险低：norm、merger 和 DeltaNet 状态参数影响面广，默认冻结并单独消融。
7. 冻结边界应沿结构边界（完整混合周期、等量视觉 block）切分，并通过打印可训练参数清单和冻结参数 hash 来验证配置真的生效。

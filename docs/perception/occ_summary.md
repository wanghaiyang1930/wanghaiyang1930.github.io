# Occupancy Network 高质量解决方案综述

## 概览

Occupancy Network（占据网络）领域目前以开源学术解决方案为主导，呈现出多样化的架构方法。基于视觉的Transformer方法（OccNet、OccFormer）建立了当前基线，使用BEVFormer编码器和3D可变形注意力机制。近期创新主要集中在通过稀疏表示（SparseOcc实现74.9% FLOPs削减）和简化架构（Fast Occupancy Network实现3倍加速）来提升效率。自监督的纯视觉方法（OccNeRF）通过时序光度一致性约束消除了对LiDAR的依赖。标准化基准测试（OpenOcc包含14亿标注体素，Occ3D）使系统性对比成为可能。

**注：** 除Tesla在2022年的公开声明外，未发现工业界/商业解决方案的可验证文献。

## 1. 学术界开源方案

### 1.1 基于Transformer的架构

#### OccNet (ICCV 2023)
- **架构特点**：使用BEVFormer编码器 + 级联体素解码器(Cascade Voxel Decoder) + 3D可变形注意力机制
- **地位**：作为ICCV 2023基线方法，用于3D占据重建
- **开源状态**：完整开源实现
- **参考**：
  - 论文：https://arxiv.org/html/2306.02851
  - 代码：https://github.com/OpenDriveLab/OccNet

#### OccFormer
- **架构特点**：将3D处理分解为双路径（局部/全局）Transformer，沿水平平面进行处理
- **开源状态**：完整开源（Apache-2.0许可证），基于mmdetection3d框架，提供预训练权重
- **评估基准**：
  - SemanticKITTI（语义场景补全任务）
  - nuScenes（LiDAR分割任务）
- **参考**：
  - 论文：https://arxiv.org/abs/2304.05316
  - 代码：https://github.com/zhangyp15/OccFormer

**可信度**：高 ✅  
*多篇同行评审论文（ICCV 2023、CVPR 2024），官方GitHub实现，所有技术细节可复现*

---

### 1.2 效率优化架构

#### Fast Occupancy Network (AMD, 2024年12月)
- **核心创新**：使用可变形2D卷积进行BEV到体素的提升，无需3D注意力机制
- **性能提升**：
  - 相比OccNet基线，推理速度提升约3倍
  - 精度提升约1.7% mIoU（ResNet50在OpenOcc上）
- **参考**：https://arxiv.org/html/2412.07163v1

#### SparseOcc (CVPR 2024)
- **核心创新**：受点云处理启发，提出无损稀疏潜在表示
- **性能提升**：
  - FLOPs削减74.9%
  - mIoU从12.8%提升至14.1%
- **参考**：
  - 论文：https://arxiv.org/abs/2404.09502
  - 代码：https://github.com/VISION-SJTU/SparseOcc

#### SimpleOccupancy
- **架构特点**：基于CNN的框架
- **性能表现**：在DDAD和nuScenes上单目深度估计性能具有竞争力
- **参考**：https://github.com/GANWANSHUI/SimpleOccupancy

**可信度**：中等 ⚠️  
*Fast Occupancy Network结果为自报告（arXiv预印本，未经同行评审）。SparseOcc经CVPR 2024同行评审。SimpleOccupancy使用温和的"具有竞争力"表述，而非SOTA声明*

---

### 1.3 自监督纯视觉方法

#### OccNeRF
- **核心创新**：无需3D/LiDAR监督，训练多相机占据网络
- **技术路线**：
  - 将2D特征直接插值到3D体积中
  - 使用带参数化坐标收缩的3D CNN处理无界空间
  - 通过跨帧时序光度一致性进行监督
- **工业意义**：消除LiDAR依赖，显著降低成本
- **参考**：https://arxiv.org/html/2312.09243v3

**可信度**：高 ✅  
*主论文（2023年12月）明确描述所有技术组件，多个独立来源确认无LiDAR特性，解决了关键的工业成本削减需求*

---

### 1.4 先进生成方法

#### CascadeOcc
- **核心创新**：将级联向量量化(VQ)机制集成到自回归框架中
- **技术特点**：
  - 使用层次化多尺度VQVAE-v2分词器
  - 以从粗到细的方式在三个尺度上将场景编码为离散标记
- **性能提升**：
  - IoU提升2.24%
  - mIoU提升4.6%
- **参考**：
  - 论文：https://arxiv.org/html/2606.27644v1
  - 代码：https://github.com/KyuminHwang/CascadeOcc

**可信度**：中等 ⚠️  
*论文较新（2026年6月，2.5个月前），有GitHub实现。技术方法通过主要来源验证，但量化收益为自报告。代表了与主流Transformer/稀疏方法不同的新兴方向*

## 2. 标准化基准测试

### OpenOcc
- **数据规模**：
  - 基于nuScenes
  - 34,149个标注帧
  - 14亿+标注体素
  - 16个语义类别
- **分辨率**：0.5m分辨率，覆盖200×200×16体积
- **参考**：https://arxiv.org/html/2306.02851

### Occ3D
- **定位**：将3D占据预测定义为综合感知任务
- **评估方法**：mIoU仅在相机观察到的体素上计算（mask_camera可见性）
- **参考**：https://github.com/Tsinghua-MARS-Lab/Occ3D

**可信度**：高 ✅  
*OpenOcc数据来自ICCV 2023论文逐字验证。Occ3D评估方法从清华MARS-Lab官方仓库确认。两个基准在后续研究中被广泛引用*

## 3. 方法论分类

### 3.1 按输入模态分类

1. **以LiDAR为中心**：LMSCNet、S3CNet、PointOcc
2. **以视觉为中心**：MonoScene、TPVFormer、VoxFormer、OccFormer、SurroundOcc
3. **多模态融合**：OpenOccupancy、OccFusion、Co-Occ

### 3.2 特征表示类型

- Volumetric（体积）
- BEV（鸟瞰图）
- Perspective View（透视图）
- Tri-Perspective View（三视角）

### 3.3 2D到3D转换策略

视觉中心方法使用三种主要转换：

1. **基于投影**：使用透视投影和双线性插值
2. **反向投影**：每像素深度实现一对一映射
3. **基于交叉注意力**：通过可变形注意力将体积特征作为查询

**可信度**：高 ✅  
*来源为综合性2024年5月综述论文，提供系统分类法。所有示例和技术细节从主要来源验证。代表学术界当前共识*

## 五、关键要点总结

### 技术趋势

1. ✅ **Transformer架构主导**：BEVFormer编码器 + 3D可变形注意力成为学术基线
2. ✅ **效率成为焦点**：稀疏表示和简化架构实现大幅性能提升
3. ✅ **纯视觉方案成熟**：自监督方法消除LiDAR依赖，降低成本
4. ✅ **标准化评估**：OpenOcc和Occ3D提供可复现的评估框架

### 注意事项

1. ⚠️ **工业实践不透明**：商业公司的实际部署方案缺乏公开信息
2. ⚠️ **性能声明需谨慎**：部分方法（Fast Occupancy Network、CascadeOcc）的性能提升为自报告，来自未经同行评审的arXiv预印本
3. ⚠️ **基准差异大**：绝对性能数字在不同基准和配置间差异显著，交叉方法对比困难
4. ⚠️ **快速演进**：领域快速发展（论文从2023年12月至2026年6月），当前SOTA可能快速变化
5. ⚠️ **数据质量问题**：验证过程中部分具体数据统计被拒绝（Occ3D特定数据、OccFormer在SemanticKITTI上的具体数字），提示引用精确基准数字时需谨慎

## 研究方法说明

本综述基于系统化的深度研究流程：

1. **范围界定**：将问题分解为5个搜索角度
2. **并行搜索**：针对每个角度执行网络搜索
3. **来源获取**：URL去重，提取前15个来源的可证伪声明
4. **对抗验证**：每个声明进行3票对抗验证（需2/3否决票才剔除）
5. **综合报告**：合并语义重复，按置信度排序，引用来源

- **处理代理数**：104个
- **工具调用次数**：346次
- **处理时间**：约12分钟
- **子代理令牌消耗**：约400万

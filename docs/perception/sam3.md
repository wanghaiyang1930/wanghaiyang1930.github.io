# SAM 3 技术方案总结

> 本文以 2025 年发布的 SAM 3（Segment Anything Model 3）为主，补充说明截至 2026 年的 SAM 3.1。这里的“检测效果”主要指开放词汇目标发现、实例分割和视频跟踪的综合效果，而不是传统固定类别检测器的单一 mAP。

## 1. 一句话概括

SAM 3 将“给定一个概念，在图像或视频中找出它的所有实例并精确分割”统一为一个 **Promptable Concept Segmentation（可提示概念分割，PCS）** 任务。用户可以输入文本、图像示例，或二者的组合；模型返回该概念对应的多个实例、每个实例的掩码、边界框和置信度，并可在视频中持续跟踪这些实例。

它不是简单地在 SAM 2 上增加一个文本编码器，而是将以下几部分组织成一个统一系统：

- **视觉编码器**：提取高分辨率图像/视频特征。
- **文本与视觉提示编码器**：将自然语言概念和参考图像转为查询条件。
- **概念级检测器**：判断图中是否存在目标概念，并预测多个候选实例。
- **掩码解码器**：从实例查询生成像素级掩码和边界。
- **视频跟踪器**：利用记忆特征在后续帧传播实例身份和掩码。
- **数据引擎**：持续生成、筛选和修正概念级图像/视频标注，形成训练闭环。

官方实现的 SAM 3 约有 **848M 参数**，由共享视觉编码器的图像检测器和视频跟踪器组成：图像检测器是受文本、几何提示和图像示例条件化的 DETR 类模型，跟踪器沿用了 SAM 2 的 Transformer 编解码结构。

## 2. 任务定义

### 2.1 输入

对一张图像或一个视频帧序列，提示可以是：

1. **文本提示**：例如 `a red car`、`all pedestrians`、`the red backpack`。
2. **图像提示**：提供一个目标实例的裁剪图、框或掩码作为视觉示例。
3. **文本 + 图像提示**：用文字限定语义，再用参考图像限定外观。
4. **视频中的交互提示**：在某一帧点击、框选或分割一个对象，随后跟踪其余帧。

### 2.2 输出

对每个匹配实例输出：

- 二值或概率掩码；
- 外接框；
- 实例置信度；
- 视频中的时序轨迹和实例 ID；
- 可选的概念存在性（presence）判断。

因此，SAM 3 可以看作“开放词汇检测 + 实例分割 + 视频对象跟踪”的统一接口。与只输出类别和框的检测器相比，它还必须解决“一个概念对应多少个对象”和“每个对象的像素边界在哪里”两个问题。

## 3. 总体架构

```text
文本提示 ──> 文本编码器 ─┐
                         ├─> 概念/实例查询 ─> 检测器 ─> 候选实例
图像提示 ──> 视觉提示编码器 ┘                       │
                                                     v
输入图像/视频 ─> 视觉骨干 ─> 多尺度视觉特征 ─> 掩码解码器 ─> masks/boxes/scores
                                                     │
                                                     v
                                        视频记忆库/跟踪器 ─> 后续帧实例轨迹
```

### 3.1 视觉编码与多尺度特征

视觉骨干网络将输入转换为具有语义和空间信息的特征。高层特征有利于识别“是什么”，低层或高分辨率特征有利于恢复边缘、细长结构和小目标。掩码解码器需要同时访问这两类信息，避免只用低分辨率语义特征导致边界过粗。

视频输入通常不能把所有帧都独立处理：一方面计算量过大，另一方面独立预测会造成 ID 切换和掩码抖动。因此，系统将当前帧特征与历史帧的对象记忆结合，使用时序信息约束后续预测。

### 3.2 文本/图像提示编码

文本编码器把概念提示映射到语义空间，视觉提示编码器把参考对象映射到外观空间。两者通过共享的查询接口进入同一个实例预测模块，使“找所有红色汽车”和“找与这张图相似的物体”不必分别设计两套模型。

文本提示的关键不是只做类别分类，而是将自然语言作为**概念条件**：概念可以是类别、属性、关系或更具体的短语。开放词汇能力由视觉-语言对齐、概念级训练数据和推理时的提示机制共同提供。

### 3.3 检测器与 presence token

SAM 3 的核心变化是加入面向“概念是否存在、存在多少个实例”的检测机制。模型为每个概念产生一组实例查询，预测每个查询是否对应真实目标，并同时回归框、掩码和置信度。

其中，**presence token** 可理解为概念级的存在性信号：它帮助模型区分“图中确实没有该概念”和“有目标但某个实例查询没有匹配到目标”。这比单纯对候选框打分更适合开放词汇的全量实例发现，也能减少无目标场景下的伪检出。

### 3.4 掩码解码器

掩码预测通常采用“实例查询 × 空间特征”的条件解码方式：查询携带对象语义，空间特征携带位置和边界信息，二者融合后得到每个实例的像素级 mask。检测器提供的框和实例查询为掩码解码提供了较强的空间先验，视觉骨干的高分辨率特征则负责边界细化。

这形成了一个重要的分工：

- 检测分支解决“有没有、在哪、是哪一个实例”；
- 掩码分支解决“精确到哪些像素”；
- presence 信号解决“这个概念整体是否存在”；
- 跟踪分支解决“下一帧是否仍是同一个实例”。

### 3.5 视频记忆与跟踪

在视频中，首帧或交互帧产生的实例查询、掩码和视觉特征会写入记忆库。后续帧通过当前视觉特征与历史记忆匹配，传播对象状态，并在必要时重新检测和修正。这样可以利用运动连续性、外观一致性和历史掩码，降低遮挡、短时模糊和姿态变化造成的断轨。

## 4. 训练与数据引擎

SAM 3 效果好的根本原因之一不是某个单独的网络模块，而是**模型、标注器和数据引擎协同设计**。

### 4.1 统一的概念分割监督

训练样本不只包含“图像-类别标签”，还尽量包含：

- 概念的文本表达；
- 图像中该概念的全部实例，而非只标一个实例；
- 每个实例的框和精细 mask；
- 正样本与概念不存在的负样本；
- 同一对象在视频中的时序对应关系。

这使模型直接学习部署时真正要做的事情：根据提示找到概念的**所有实例**，而不是把分割模型和分类器在推理阶段生硬拼起来。

### 4.2 SA-Co 数据引擎

SAM 3 的数据引擎 SA-Co（Segment Anything with Concepts）围绕“概念”组织数据。高层流程可以概括为：

1. 从自然图像、视频和概念词表中提出候选概念；
2. 使用视觉-语言模型、检测器、分割器和跟踪器产生初始伪标注；
3. 通过人工标注和质量检查修正边界、实例遗漏、概念歧义与负样本；
4. 将高质量样本加入训练集，重新训练模型；
5. 用新模型发现长尾概念和难例，再回流数据引擎。

官方资料将该体系描述为规模很大的概念级数据引擎：自动标注了超过 **400 万个唯一概念**。对应的 SA-Co 评测包含约 **27 万个唯一概念**，并覆盖图像和视频；数据中包含 hard negative，用于评估概念不存在或容易混淆时的行为。具体数据版本应以官方论文、数据许可和仓库说明为准。

### 4.3 难例与负样本

检测效果不仅取决于正样本数量，也取决于模型是否见过容易混淆的负样本，例如：

- 同类但不同实例；
- 外观相似但语义不同的物体；
- 部分遮挡、截断、极小目标；
- 文本概念不成立的图像；
- 一张图中目标数量很多的拥挤场景。

presence token 和概念级负样本共同帮助模型学习“何时应该不输出”，从而降低开放词汇提示下的幻检。

## 5. 为什么检测和分割效果好

### 5.1 从固定类别检测升级为概念条件预测

传统检测器通常在固定类别集合上训练分类头；推理时遇到训练类别之外的词，模型没有天然的分类通道。SAM 3 直接让文本/图像提示参与实例查询生成，类别空间由提示定义，因此能够处理开放词汇、属性短语和视觉示例。

### 5.2 检测、分割、存在性联合优化

如果先检测再独立分割，检测框错误会把错误传给分割器；如果只做像素分割，又缺少实例数量和实例身份约束。SAM 3 将框、mask、概念存在性和实例匹配放入统一训练目标，多个任务之间可以互相提供约束：

- 框提供粗粒度位置先验；
- mask 提供精细空间监督；
- 匹配损失抑制重复预测和漏检；
- presence 监督抑制无目标时的误报；
- 时序记忆提供视频连续性约束。

### 5.3 大规模、多样化、概念级数据

大模型的泛化能力很大程度上来自数据覆盖范围。SA-Co 不仅扩大了图片和视频数量，更重要的是扩大了概念、短语、外观变化、场景变化和实例数量的覆盖。模型因此更可能遇到与真实使用相似的表达和难例，而不是只记住少数数据集的类别名称。

### 5.4 视觉语言语义与像素级视觉细节结合

语言模型或纯视觉语言模型擅长语义，但通常不直接产生精细像素边界；传统分割模型边界精确，却缺少开放词汇理解。SAM 3 通过文本/图像提示提供语义条件，同时保留高分辨率视觉特征和掩码解码器，兼顾“找对对象”和“切准边界”。

### 5.5 视频时序信息降低抖动和漏检

视频中相邻帧通常高度相关。利用历史记忆可以把上一帧的目标位置、外观和掩码作为先验，在短时遮挡、运动模糊和光照变化下维持轨迹；重新检测机制又能在长时遮挡或目标重新出现时恢复对象。这比逐帧独立检测更稳定。

### 5.6 端到端统一训练减少系统误差

模型不依赖多个完全独立、接口损失较大的模块串联。提示编码、概念检测、掩码生成和视频跟踪在相同任务定义下协同训练，推理时的目标与训练时的监督一致，因此减少了“分类器认为是目标、分割器却切错对象”一类的级联误差。

## 6. 与前代模型的关系

| 方案 | 主要提示 | 主要能力 | 关键限制 |
|---|---|---|---|
| SAM | 点、框、粗 mask | 单图通用分割 | 不负责开放词汇自动发现全部实例 |
| SAM 2 | 点、框、mask、视频交互 | 图像分割和视频对象跟踪 | 概念级全量发现能力不是核心目标 |
| SAM 3 | 文本、图像示例、交互提示 | 开放词汇全实例检测/分割/跟踪 | 计算量和数据依赖更高 |
| SAM 3.1 | SAM 3 的 2026 年更新 | 以 Object Multiplex 共享记忆联合处理多目标跟踪，官方称在 128 个对象时单张 H100 约有 7 倍速度提升 | 应以对应版本权重、接口和许可证为准 |

SAM 3 并不是“只把 SAM 2 的 mask 做得更精细”。它的能力边界发生了变化：从“用户指出一个对象，模型把它分出来”扩展到“用户描述一个概念，模型主动找到该概念的全部实例”。

## 7. 推理方案

### 7.1 图像推理

```text
1. 读取图像并进行尺寸、归一化等预处理
2. 编码文本提示或图像提示
3. 运行视觉骨干，得到多尺度特征
4. 生成概念级实例查询和 presence 预测
5. 预测框、mask、置信度
6. 按概念存在性、置信度和 mask 质量过滤
7. 输出实例结果，并按需要做可视化或下游融合
```

### 7.2 视频推理

```text
1. 在首帧用文本、框、点或 mask 初始化对象
2. 将实例查询和视觉记忆写入跟踪器
3. 对后续帧执行记忆匹配与 mask 传播
4. 周期性或在置信度下降时重新检测
5. 处理遮挡、出入画和 ID 恢复
6. 输出带实例 ID 的时序 mask、框和轨迹
```

### 7.3 工程侧的关键参数

- **提示设计**：文本尽量明确对象、属性和数量语义；长文本不一定优于简洁短语。
- **阈值策略**：分别校准 presence 阈值、实例置信度阈值和 mask 质量阈值，避免用一个阈值覆盖所有概念。
- **分辨率策略**：小目标和细长结构对输入分辨率敏感，可采用切图/多尺度推理，但要处理跨切片重复实例。
- **视频刷新策略**：短视频可充分利用记忆；长视频应设置周期性重检测和记忆淘汰，防止漂移累积。
- **结果后处理**：可做低质量 mask 过滤、实例去重、时序平滑和轨迹生命周期管理，但不应把后处理当成弥补提示歧义的主要手段。

## 8. 评价指标与效果解读

建议至少分别评估以下维度，而不是只看一个总分：

- **检测**：概念存在性准确率、召回率、Precision/Recall、box AP；
- **实例分割**：mask AP、IoU、边界质量、小目标召回率；
- **开放词汇**：未见类别、长尾概念、属性短语和视觉示例提示；
- **视频**：IDF1、HOTA、ID switch、轨迹断裂率、时序 mask 稳定性；
- **工程指标**：单图/单帧延迟、显存、吞吐、视频端到端 FPS。

官方报告中的性能通常对应特定数据集、输入分辨率、硬件、提示格式和后处理设置。不能直接把论文中的 mask AP 或 FPS 等同于任意业务场景下的检测精度；在自动驾驶、工业缺陷或低照度场景中，应使用业务数据重新标定阈值并验证长尾失败案例。

## 9. 局限性与落地风险

1. **开放词汇不等于无条件理解**：提示过于模糊、概念在图像中不可见或多个概念边界不清时，结果仍可能不稳定。
2. **小目标和极端遮挡**：像素信息不足时，任何分割器都难以恢复真实边界；提高分辨率会增加显存和延迟。
3. **实例数量很多时成本上升**：全量概念发现需要更多候选查询和更复杂的掩码解码。
4. **视频长时漂移**：记忆错误会被传播，必须配合置信度监控、重检测和轨迹恢复。
5. **领域迁移**：医学、红外、鱼眼、车载环视、工业相机等域与互联网图像差异大，建议用少量业务标注做评测和适配。
6. **许可证和数据合规**：商用前必须核对模型权重、代码、训练数据及衍生标注的许可范围，不应仅依据论文中的描述做合规判断。
7. **资源消耗**：SAM 3 级别模型更适合服务器或高性能边缘设备；端侧部署通常需要蒸馏、量化、裁剪、低分辨率或级联策略。

## 10. 面向感知系统的推荐集成方案

对于已有固定类别检测器的感知系统，建议采用“专用检测器保底 + SAM 3 开放词汇增强”的混合架构：

```text
传感器输入
   ├─> 实时固定类别检测器 ─> 高频、低延迟主链路
   └─> SAM 3 概念分割 ────> 长尾发现、交互目标、难例复核
                         ↓
              结果融合/跟踪/质量监控
                         ↓
                 下游规划、标注或检索
```

推荐的工程分工：

- 对安全关键、类别固定且有严格时延要求的目标，保留专用轻量检测器；
- 用 SAM 3 处理长尾目标、临时概念、用户交互和自动标注；
- 对 SAM 3 输出增加置信度、mask 面积、边界质量和轨迹稳定性监控；
- 将高价值误检、漏检和新概念样本回流数据引擎，形成业务闭环；
- 离线标注阶段可使用较高分辨率和更复杂提示，在线阶段采用缓存、ROI、周期重检和量化模型控制成本。

## 11. 结论

SAM 3 的高检测/分割效果来自系统性组合，而不是单一“更大的 backbone”：

1. 用文本和图像提示定义开放词汇概念；
2. 用概念级检测器和 presence token 发现全部实例并抑制无目标误报；
3. 用实例查询与高分辨率特征联合生成精细 mask；
4. 用大规模概念级数据引擎覆盖长尾概念、负样本和难例；
5. 用视频记忆和跟踪利用时序连续性；
6. 用端到端联合训练减少检测、分割、跟踪之间的级联误差。

所以，SAM 3 更准确的定位是一个“可提示的开放词汇概念分割系统”，而不是传统意义上只输出固定类别框的检测器。实际选型时，应同时比较准确率、开放词汇召回率、mask 质量、视频稳定性、延迟、显存和许可证，而不能只看单一 benchmark 数字。
